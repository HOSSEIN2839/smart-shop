# مستندات راه‌اندازی و وضعیت سرور Smart Shop

## 1. هدف سند

این سند مشخصات زیرساخت، وضعیت سرویس‌ها، تنظیمات شبکه و وضعیت امنیتی سرور پروژه Smart Shop را ثبت می‌کند.

اطلاعات این مستند بر اساس بررسی انجام‌شده روی سرور در تاریخ 2026-11-01 تهیه شده است. مواردی که هنوز تأیید نشده‌اند، صریحاً مشخص شده‌اند.

## 2. مشخصات سرور

| مشخصه | مقدار |
|---|---|
| ارائه‌دهنده VPS | ParsVDS |
| نام میزبان | `id-291008` |
| سیستم‌عامل | Ubuntu 24.04 LTS |
| معماری | x86_64 |
| آدرس IP | `141.11.1.126` |
| پورت SSH | `9011` |
| دامنه اختصاصی | تنظیم نشده |

## 3. دسترسی SSH

اتصال مدیریتی به سرور از طریق SSH و پورت اختصاصی 9011 انجام می‌شود.

نمونه دستور اتصال:

```bash
ssh -p 9011 root@141.11.1.126
```

نکات امنیتی:

- پورت SSH برابر `9011` است و نباید بدون هماهنگی تغییر کند.
- رمز عبور و اطلاعات محرمانه اتصال نباید در مخزن پروژه یا مستندات عمومی قرار بگیرند.
- دسترسی مدیریتی سرور باید فقط در اختیار افراد مجاز باشد.

## 4. سرویس‌های نصب‌شده

| سرویس | نسخه بررسی‌شده | وضعیت |
|---|---|---|
| Apache | 2.4.58 | فعال |
| PHP CLI | 8.3.6 | نصب‌شده |
| MySQL | 8.0.46 | فعال |
| Git | 2.43.0 | نصب‌شده |

آزمون پیکربندی Apache با دستور زیر انجام شده است:

```bash
apache2ctl configtest
```

نتیجه:

```text
Syntax OK
```

در زمان بررسی، هشدار `AH00558` درباره تنظیم نبودن `ServerName` نیز مشاهده شده است. این هشدار به‌تنهایی به معنی خراب بودن پیکربندی Apache نیست.

## 5. افزونه‌های PHP

افزونه‌های زیر در محیط PHP بررسی و تأیید شده‌اند:

- curl
- json
- mbstring
- openssl
- PDO
- pdo_mysql

نسخه PHP بررسی‌شده مربوط به محیط CLI است. تطابق کامل نسخه و افزونه‌های PHP در محیط Apache باید در صورت نیاز جداگانه بررسی شود.

## 6. تنظیمات فایروال

فایروال UFW فعال است.

سیاست‌های اصلی:

- ورودی‌های غیرمجاز به‌صورت پیش‌فرض مسدود هستند.
- ارتباطات خروجی مجاز هستند.

پورت‌های مجاز:

| پورت | کاربرد |
|---|---|
| 9011/TCP | اتصال SSH |
| 80/TCP | ارتباط HTTP |
| 443/TCP | ارتباط HTTPS در صورت راه‌اندازی |

قوانین فوق برای IPv4 و IPv6 مشاهده شده‌اند.

## 7. ساختار مسیرهای پروژه

مسیرهای مهم بررسی‌شده:

| مسیر | کاربرد |
|---|---|
| `/var/www/html` | ریشه عمومی وب‌سایت و DocumentRoot فعلی Apache |
| `/var/www/smart-shop-private` | محل نگهداری فایل‌های خصوصی و بخش‌های داخلی پروژه |
| `/var/www/smart-shop-private/app` | کدهای داخلی برنامه |
| `/var/www/smart-shop-private/config` | تنظیمات داخلی برنامه |
| `/var/www/smart-shop-private/logs` | فایل‌های گزارش برنامه |
| `/var/www/smart-shop-private/backups` | محل نگهداری نسخه‌های پشتیبان |

مسیر `/var/www/smart-shop` در زمان بررسی وجود نداشت.

نکته: قبل از جابه‌جایی یا جایگزینی فایل‌ها باید ارتباط واقعی فایل‌های عمومی با فایل‌های داخلی پروژه بررسی شود. نباید کل پروژه بدون تفکیک در DocumentRoot قرار بگیرد.

## 8. پایگاه داده

پایگاه داده پروژه با نام زیر تنظیم شده است:

```text
smart_shop
```

وضعیت سرویس MySQL فعال است.

اتصال برنامه به پایگاه داده در آزمون قبلی موفق بوده و اجرای دستور آزمایشی `SELECT 1` نتیجه مورد انتظار را برگردانده است.

اطلاعات اتصال، رمز عبور و فایل تنظیمات پایگاه داده نباید در این مستند یا مخزن عمومی قرار بگیرند.

## 9. تنظیمات سرویس هوش مصنوعی

پروژه برای ارتباط با سرویس هوش مصنوعی از API سازگار با OpenAI استفاده می‌کند.

| مشخصه | مقدار |
|---|---|
| حالت اتصال | Live |
| Base URL | `https://api.avalai.ir/v1` |
| مسیر درخواست | `chat/completions` |
| مدل | `deepseek-v4.1-flash` |
| Temperature | `0.3` |
| Timeout | 30 ثانیه |
| Connect Timeout | 10 ثانیه |
| تعداد Retry | 1 |

کلید API در فایل محیطی جداگانه نگهداری می‌شود و نباید در کد عمومی، مخزن یا گزارش‌ها افشا شود.

فایل محیطی بررسی‌شده:

```text
/etc/avalai.env
```

مجوز فایل به‌گونه‌ای تنظیم شده که کاربر `www-data` امکان خواندن آن را دارد.

## 10. تنظیمات نشست کاربر

برخی تنظیمات بررسی‌شده نشست:

| گزینه | مقدار |
|---|---|
| نام اختصاصی Session | تنظیم شده |
| تعداد پیام‌های تاریخچه | 12 |
| حداکثر طول پیام | 500 کاراکتر |
| HttpOnly | فعال |
| SameSite | Lax |
| Secure | وابسته به HTTPS |

از آنجا که HTTPS هنوز راه‌اندازی نشده، ویژگی Secure برای کوکی نشست در وضعیت فعلی فعال نیست.

## 11. وضعیت امنیتی وب‌سرور

موارد زیر در بررسی انجام‌شده مشاهده شده‌اند:

- غیرفعال بودن فهرست‌کردن محتویات پوشه‌ها با `Options -Indexes`
- مسدود بودن دسترسی به فایل‌های مخفی
- مسدود بودن دسترسی به برخی فایل‌های پشتیبان و آرشیو
- وجود هدر `X-Content-Type-Options`
- وجود هدر `Referrer-Policy`
- وجود هدر `Permissions-Policy`
- وجود Content Security Policy در صفحه اصلی

هدر HSTS در زمان بررسی مشاهده نشده است؛ زیرا HTTPS هنوز پیکربندی نشده است.

برخی هدرها در پاسخ صفحه اصلی تکراری مشاهده شده‌اند و بهتر است در بازبینی بعدی، محل تنظیم آن‌ها یکپارچه شود.

## 12. آزمون‌های انجام‌شده

| آزمون | نتیجه |
|---|---|
| اتصال SSH | موفق |
| فعال بودن Apache | موفق |
| فعال بودن MySQL | موفق |
| بررسی Syntax آپاچی | موفق |

مسیرهای API بررسی‌شده:

```text
/api/chat.php
/api/session.php
/api/cart.php
```

پاسخ 405 برای درخواست GET در این مسیرها با محدود بودن این endpointها به POST سازگار است.

## 13. محدودیت‌ها و موارد باقی‌مانده

1. دامنه اختصاصی برای پروژه تنظیم نشده است.
2. HTTPS و گواهی SSL هنوز راه‌اندازی نشده‌اند.
3. HSTS هنوز فعال نیست.
4. هشدار `ServerName` در Apache باقی مانده است.
5. یکپارچه‌سازی هدرهای امنیتی تکراری نیازمند بازبینی است.
6. آزمون درخواست واقعی چت به API هوش مصنوعی در ممیزی انجام نشده است؛ زیرا ممکن است هزینه API ایجاد کند.
7. مسیرهای عمومی و خصوصی پروژه باید هنگام هر استقرار با دقت تفکیک شوند.

## 14. نتیجه‌گیری

در زمان انجام ممیزی، سرویس‌های اصلی Apache و MySQL فعال بوده‌اند، سرور از طریق SSH در دسترس بوده و صفحه اصلی سایت پاسخ HTTP 200 ارائه کرده است.

اتصال برنامه به پایگاه داده نیز در آزمون قبلی موفق بوده است.

با این حال، به دلیل نبود دامنه اختصاصی و HTTPS و باقی‌ماندن برخی موارد امنیتی و پیکربندی، وضعیت سرور نباید به‌عنوان استقرار نهایی و کاملاً امن اینترنتی توصیف شود.

این مستند باید با تغییرات مهم زیرساخت و تنظیمات سرور به‌روزرسانی شود.
