# راهنمای استقرار پروژه Smart Shop

## 1. هدف سند

این راهنما روش انتشار و به‌روزرسانی دستی پروژه Smart Shop روی سرور را توضیح می‌دهد.

روش فعلی استقرار پروژه، بارگذاری دستی فایل‌ها است و از `git pull` روی سرور برای به‌روزرسانی استفاده نمی‌شود.

## 2. مشخصات اتصال به سرور

| مشخصه | مقدار |
|---|---|
| IP سرور | `141.11.1.126` |
| پورت SSH | `9011` |
| نام کاربری مدیریتی | `root` |
| مسیر عمومی وب | `/var/www/html` |
| مسیر خصوصی پروژه | `/var/www/smart-shop-private` |

نمونه اتصال از Windows PowerShell:

```powershell
ssh -p 9011 root@141.11.1.126
```

اطلاعات محرمانه اتصال باید فقط از طریق روش امن در اختیار افراد مجاز قرار بگیرد.

## 3. ساختار مسیرها

در سرور دو مسیر اصلی وجود دارد:

### مسیر عمومی

```text
/var/www/html
```

این مسیر DocumentRoot فعلی Apache است و فایل‌هایی که باید مستقیماً از طریق مرورگر در دسترس باشند، در بخش عمومی وب قرار می‌گیرند.

### مسیر خصوصی

```text
/var/www/smart-shop-private
```

این مسیر برای نگهداری بخش‌های داخلی پروژه استفاده می‌شود.

بخش‌هایی مانند تنظیمات، کدهای داخلی، گزارش‌ها و نسخه‌های پشتیبان نباید بدون بررسی امنیتی در مسیر عمومی وب قرار بگیرند.

**مهم:** قبل از استقرار، ارتباط فایل‌های ورودی عمومی و APIها با کدهای داخلی برنامه بررسی شود. فایل‌ها نباید صرفاً بر اساس نام پوشه جابه‌جا شوند.

## 4. روش فعلی انتشار

انتشار پروژه به‌صورت دستی انجام می‌شود.

مراحل کلی:

1. دریافت نسخه مورد تأیید پروژه از مخزن رسمی تیم.
2. بررسی تغییرات و فایل‌های جدید.
3. تهیه نسخه پشتیبان از فایل‌های فعلی سرور.
4. بارگذاری فایل‌های تغییرکرده در مسیر صحیح.
5. بررسی مالکیت و مجوز دسترسی فایل‌ها.
6. بررسی پیکربندی Apache و PHP.
7. انجام آزمون‌های پس از استقرار.

در حال حاضر اجرای `git pull` روی سرور بخشی از فرایند انتشار نیست.

## 5. نکات مهم قبل از انتشار

پیش از جایگزینی فایل‌ها:

- از نسخه فعلی فایل‌های در حال تغییر نسخه پشتیبان تهیه کنید.
- مطمئن شوید نسخه جدید از مخزن رسمی پروژه دریافت شده است.
- فایل‌های تنظیمات محرمانه را با نسخه مخزن جایگزین نکنید.
- فایل‌های پایگاه داده و اطلاعات اتصال را بدون هماهنگی تغییر ندهید.
- فایل‌های عمومی و خصوصی را از یکدیگر تفکیک کنید.
- تغییرات دیتابیس را فقط طبق دستورالعمل تأییدشده تیم اجرا کنید.

## 6. فایل‌هایی که نباید در مسیر عمومی قرار بگیرند

موارد زیر نباید به‌صورت مستقیم از وب قابل دریافت باشند:

| فایل یا پوشه | دلیل |
|---|---|
| `.env` | ممکن است حاوی کلیدها و اطلاعات محرمانه باشد |
| فایل تنظیمات پایگاه داده | حاوی اطلاعات اتصال به دیتابیس |
| `config/` | شامل تنظیمات داخلی برنامه |
| `database/` | شامل فایل‌ها و اطلاعات ساختار دیتابیس |
| `backups/` | شامل نسخه‌های پشتیبان |
| `logs/` | ممکن است اطلاعات داخلی و خطاهای برنامه را افشا کند |
| فایل‌های `.sql` | ممکن است حاوی داده‌های پایگاه داده باشند |
| فایل‌های `.zip` و `.tar.gz` | ممکن است کل پروژه یا اطلاعات حساس را دربر داشته باشند |
| فایل‌های `.bak` و `.old` | نسخه‌های قدیمی و پشتیبان کد |
| فایل‌های دارای کلید API یا رمز عبور | اطلاعات محرمانه |

فایل‌های محرمانه باید خارج از DocumentRoot یا در مسیری با دسترسی محدود نگهداری شوند.

## 7. بررسی پس از استقرار

پس از بارگذاری نسخه جدید، بررسی‌های زیر انجام شوند.

### بررسی وضعیت Apache

```bash
systemctl status apache2 --no-pager
```

### بررسی وضعیت MySQL

```bash
systemctl status mysql --no-pager
```

### بررسی صحت پیکربندی Apache

```bash
apache2ctl configtest
```

نتیجه مورد انتظار:

```text
Syntax OK
```

### بررسی پاسخ صفحه اصلی

```bash
curl -I http://127.0.0.1/
```

در صورت سالم بودن صفحه اصلی، انتظار می‌رود پاسخ HTTP موفق مانند `200 OK` دریافت شود.

### بررسی فایل‌های PHP

برای بررسی نحوی یک فایل PHP:

```bash
php -l /path/to/file.php
```

مسیر فایل باید با مسیر واقعی آن در سرور جایگزین شود.

### بررسی گزارش خطاهای Apache

```bash
tail -n 50 /var/log/apache2/error.log
```

در صورت مشاهده خطاهای جدید، پیش از اعلام موفقیت استقرار باید علت آن‌ها بررسی شود.

## 8. بررسی API

برخی endpointهای پروژه فقط درخواست POST را می‌پذیرند.

مسیرهای بررسی‌شده:

```text
/api/chat.php
/api/session.php
/api/cart.php
```

درخواست GET به این مسیرها می‌تواند پاسخ `405 Method Not Allowed` برگرداند. این پاسخ به‌تنهایی نشانه خرابی API نیست.

برای آزمون عملی درخواست POST باید از داده آزمایشی معتبر و مجوز لازم استفاده شود. آزمون endpoint چت ممکن است باعث ارسال درخواست به API هوش مصنوعی و ایجاد هزینه شود؛ بنابراین بدون هماهنگی انجام نشود.

## 9. بررسی دسترسی عمومی

پس از انتشار، صفحه اصلی از طریق آدرس زیر قابل بررسی است:

```text
http://141.11.1.126/
```

در وضعیت فعلی پروژه:

- دسترسی از طریق IP انجام می‌شود.
- دامنه اختصاصی تنظیم نشده است.
- HTTPS راه‌اندازی نشده است.

بنابراین نباید آدرس HTTPS یا دامنه‌ای را به‌عنوان آدرس عملیاتی پروژه اعلام کرد.

## 10. بازگشت به نسخه قبلی (Rollback)

اگر پس از انتشار، سایت با خطا مواجه شد:

1. انتشار فایل‌های جدید را متوقف کنید.
2. گزارش خطای Apache و وضعیت فایل‌های تغییرکرده را بررسی کنید.
3. نسخه پشتیبان تهیه‌شده پیش از انتشار را شناسایی کنید.
4. فایل‌های قبلی را به مسیر اصلی بازگردانید.
5. صحت پیکربندی Apache را بررسی کنید.
6. وضعیت صفحه اصلی و APIها را دوباره آزمایش کنید.

تغییرات پایگاه داده ممکن است با بازگرداندن فایل‌ها به حالت قبلی برنگردند. بازیابی دیتابیس باید جداگانه و طبق نسخه پشتیبان معتبر انجام شود.

## 11. موارد ممنوع در فرایند استقرار

- قراردادن رمزها و کلیدهای API در مخزن عمومی
- قرار دادن فایل‌های پشتیبان در DocumentRoot
- انتشار مستقیم فایل‌های تنظیمات داخلی
- جایگزینی فایل تنظیمات سرور با نسخه‌ای که اطلاعات محرمانه را حذف یا تغییر می‌دهد
- تغییر پورت SSH یا قوانین فایروال بدون هماهنگی
- اجرای تغییرات مخرب دیتابیس بدون نسخه پشتیبان
- اعلام موفقیت استقرار بدون انجام آزمون‌های پس از انتشار

## 13. نتیجه‌گیری

استقرار فعلی Smart Shop به‌صورت دستی انجام می‌شود. مسیر عمومی وب `/var/www/html` و مسیر خصوصی پروژه `/var/www/smart-shop-private` است.

هر بار انتشار باید با تهیه نسخه پشتیبان، تفکیک فایل‌های عمومی و خصوصی و انجام آزمون‌های پس از استقرار همراه باشد.

این راهنما باید در صورت تغییر روش انتشار، مسیرها یا ساختار پروژه به‌روزرسانی شود.
